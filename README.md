# Orbit Cache

**缓存用完就扔的自动清洁工。**

装上就干活：停用插件时顺手清内存，到点自动清缓存，缓存目录自己搜自己认。
你只需要点一次「试运行」，看看它到底会删什么。

---

## 一、先做这一步：让 NapCat 开一个服务端

插件是**客户端**，要主动去连 NapCat。而很多部署里 NapCat 只配了「反向连接」
（`websocketClients`）——它自己不对外监听任何端口，**任何客户端都连不上它**。
所以第一次使用前，需要在 NapCat 里给它加一个服务端。

### 步骤

1. 打开 **NapCat WebUI**，地址通常是 `http://<服务器IP>:6099/webui`，
   用 NapCat 登录 Token 进去。
2. 左侧点 **网络配置**。
3. 点 **添加**，类型选 **HTTP服务器**。
4. 按下面填：

   | 字段 | 填什么 | 说明 |
   |---|---|---|
   | 名称 | `Orbit Cache` | 随便起，方便自己认 |
   | 启用 | **开** | 必须开 |
   | 主机 | `0.0.0.0` | 容器内监听所有网卡 |
   | 端口 | `3000` | 同容器用 3000；多个实例请各填各的，别撞号 |
   | 消息Post格式 | `array` | 默认即可 |
   | **Token** | **留空** | 留空最省事：省掉鉴权，也就没有「Token 变了要重配」的问题 |
   | 调试 | 关 | |

5. **保存**，然后在 NapCat 里**重启一次**让配置生效。
6. 回到本插件面板的「NapCat 实例」，点「添加实例」，地址填：

   ```text
   同容器：      http://127.0.0.1:3000
   跨容器：      http://napcat:3000     ← 把 127.0.0.1 换成 NapCat 的服务名
   WebSocket：   ws://127.0.0.1:3001  ← 若你选的是 WebSocket 服务端
   ```

7. Token **留空**，点「保存实例」。插件会立刻去连并自动解析。
8. 点顶部 **「试运行（不删）」** 确认一切正常。

> 也可以在 NapCat 的 `config/onebot11_<QQ号>.json` 里直接加：
> ```json
> { "network": { "httpServers": [
>   { "name": "Orbit Cache", "enable": true, "host": "0.0.0.0", "port": 3000, "token": "" }
> ] } }
> ```

**多个 Bot / 多个 NapCat？** 每个实例各加一个服务端（端口别撞号），
然后在本插件面板点「添加实例」，一行一个，各自独立的 Token 与清理间隔。

## 二、它会自动做什么

| 层 | 触发时机 | 依赖 |
|---|---|---|
| 停用插件的内存模块 | 插件一被停用/卸载**当场**清理 | 不需要 NapCat |
| NapCat 协议缓存 | 每 12 小时一次，逐实例调用 `clean_cache` | 需要服务端 |
| NapCat 文件缓存 | 目录总量 > 1 MiB 时，从最旧文件删到 85% | 只需要目录可见 |
| AstrBot 磁盘缓存 | 占用 > 16 MiB 时清理 | 不需要 NapCat |

### 缓存目录不用你填

`napcat_cache_dirs` 留空即可，插件会自己搜并接管，前提是同时满足：

1. 目录名像缓存（`temp` / `cache` / `cache_temp` / `temp_cache`）
   —— 这一条就自动排除了 NapCat 实例根目录（里面含 `config/` 与程序本体）
2. 里面没有关键配置文件（`onebot11*.json`、`napcat.json`、`webui.json`、
   `napcat.mjs`、`package.json` 等）

不满足的目录会出现在面板上但标为「不建议使用」，自动接管不会碰它们。
你手填 `napcat_cache_dirs` 时以手填为准。

**即使目录被手动填成实例根目录，清理时也不会删除关键文件名**——
这层保护独立于自动接管存在。

### Token 不用你填

每次连接前从 NapCat 的 `onebot11*.json`、AstrBot 自己的平台配置、环境变量里
收集候选，**逐个发真实请求验证**，留下第一个能通的。运行中收到 401/403 会
立刻重新解析并重试一次。所以 NapCat 重启换了 Token 也能自己跟上。

## 三、试运行：先看会不会删

面板顶部有 **「试运行（不删）」**。它会告诉你：

- 每个缓存目录当前多大、会不会超阈值
- 触发的话会删几个文件、共多少字节
- 前几个将被删除的文件路径
- 待清的插件模块数

**点它不会删除任何东西，也不改状态。** 确认无误后再点「立即体检」或等下一次自动体检。

## 四、聊天指令

只有一条（仅管理员、需私聊）：

| 指令 | 作用 |
|---|---|
| `/orbit` | 四层状态 + 调度速览 |
| `/orbit clean` | 立即无视阈值强制清理全部 |
| `/orbit on` / `/orbit off` | 开启 / 暂停自动清理 |
| `/orbit purge <插件ID>` | 立即清某个插件的内存模块 |

v1.x 的 `orbit_*` 旧指令仍可用，每次回复会附一行弃用提示。

## 五、配置项

面板上能改的都建议在面板改（保存即生效并重建定时任务）。
下面是配置页里值得知道的几项：

| 配置 | 默认 | 说明 |
|---|---:|---|
| `auto_enabled` | `true` | 总开关。关掉就不体检、也不清内存 |
| `sweep_cron` | `*/15 * * * *` | 体检频率。想固定深夜可填 `30 3 * * *` |
| `auto_clean_plugin_modules` | `true` | 建议别关。AstrBot 停用插件不清内存，靠它兜住泄漏 |
| `auto_adopt_cache_dirs` | `true` | 自动接管搜索到的安全目录 |
| `napcat_cache_threshold_mb` | `1` | 超过才清，删到 85% |
| `napcat_cache_min_age_minutes` | `10` | 正在用的临时文件不会被删，别调到 0 以下 |
| `astrbot_cache_threshold_mb` | `16` | 定得低是为了能真正触发；AstrBot 临时缓存删了会重新生成 |
| `napcat_protocol_interval_hours` | `12` | 一天两次，对个人 Bot 够用 |
| `napcat_config_dirs` | `[]` | 额外搜索根，很少需要填 |
| `onebot_access_token` | 空 | 一般留空走自动解析 |

## 六、遇到问题看这里

| 面板显示 | 含义 | 该做什么 |
|---|---|---|
| `连接正常` | 通了 | 不用管 |
| `服务没启动` | 连接被拒（`ECONNREFUSED`） | NapCat 没在跑，或地址/端口填错 |
| `服务无响应` | 连上了但超时 | 防火墙拦截，或 NapCat 卡住 |
| `主机名解析失败` | DNS 解析不了 | 跨容器要写服务名且在同一网络 |
| `需要 Token` / `Token 无效` | 401/403，连接已建立 | 这时才轮到 Token |

**传输层出问题时，Token 输入框会被禁用**——改它不会有任何用。

> ⚠️ 看到「端口已被占用 / Address already in use」？**那不是插件发的**。
> 插件只做客户端，从不 bind 端口。那条消息来自尝试监听 3000 的进程
> （多半是你启动 NapCat HTTP 服务端的脚本），或者启动它时端口已被占用。

### 已知边界

- 读不到 NapCat 配置文件时，**没有任何程序能凭空知道它的 Token**，需手填。
  插件会如实报「需要 Token」，不会谎报成「无需凭据」。
- 四个 NapCat 适配器的 Token 各自独立。反向 WS 配的 token 不会自动适用于
  新加的 HTTP 服务端，要复用得在 HTTP 服务端上填相同值。
- 无论 NapCat 通不通，停用插件内存与 AstrBot 磁盘缓存这两层照常工作。

### 故障排查

| 现象 | 排查方向 |
|---|---|
| 面板显示「未注册」 | 检查 `sweep_cron` 是否合法，或 `auto_enabled` 是否已关 |
| 刚热重载过就显示「未注册」 | 本插件 `initialize()` 会自动重建任务；仍异常看日志 `Orbit Cache 注册定时任务失败` |
| NapCat 文件缓存层显示未启用 | 点「自动探测目录」看搜索结果；开着的自动接管会自动使用安全目录 |
| 停用插件模块数没归零 | 确认 `auto_clean_plugin_modules` 已开；重载后可用面板的「立即清理」 |
| 试运行说「不会删除」 | 当前占用确实没超阈值。点「强制全清」可以无视阈值立刻执行 |

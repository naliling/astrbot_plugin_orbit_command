# Orbit Cache

**缓存用完就扔的自动清洁工。**

装上就干活：停用插件时顺手清内存，到点自动清缓存，缓存目录自己搜自己认。
你只需要点一次「试运行」，看看它到底会删什么。

---

## 一、先做这一步：让 NapCat 开一个服务端

插件是**客户端**，要主动去连 NapCat。而很多部署里 NapCat 只配了「反向连接」
（`websocketClients`）——它自己不对外监听任何端口，**任何客户端都连不上它**。
所以第一次使用前，需要在 NapCat 里给它加一个服务端。

### 步骤

1. 打开 **NapCat WebUI**，地址通常是 `http://<服务器IP>:6099/webui`，
   用 NapCat 登录 Token 进去。
2. 左侧点 **网络配置**。
3. 点 **添加**，类型选 **HTTP服务器**。
4. 按下面填：

   | 字段 | 填什么 | 说明 |
   |---|---|---|
   | 名称 | `Orbit Cache` | 随便起，方便自己认 |
   | 启用 | **开** | 必须开 |
   | 主机 | `0.0.0.0` | 容器内监听所有网卡 |
   | 端口 | `3000` | 同容器用 3000；多个实例请各填各的，别撞号 |
   | 消息Post格式 | `array` | 默认即可 |
   | **Token** | **留空** | 留空最省事：省掉鉴权，也就没有「Token 变了要重配」的问题 |
   | 调试 | 关 | |

5. **保存**，然后在 NapCat 里**重启一次**让配置生效。
6. 回到本插件面板的「NapCat 实例」，点「添加实例」，地址填：

   ```text
   同容器：      http://127.0.0.1:3000
   跨容器：      http://napcat:3000     ← 把 127.0.0.1 换成 NapCat 的服务名
   WebSocket：   ws://127.0.0.1:3001  ← 若你选的是 WebSocket 服务端
   ```

7. Token **留空**，点「保存实例」。插件会立刻去连并自动解析。
8. 点顶部 **「试运行（不删）」** 确认一切正常。

> 每层卡片上还有一个 **「强清这层」**，只无视该层阈值立即动手，其它层不受影响——
> 比「强制全清」更精准，尤其是那些本来就没什么可清的层。
>
> 「强制全清」如果一个字节都没释放，会明说「本来就已经是干净的」，
> 而不是报一个「N 层执行了清理，释放 0 B」。
>
> 面板里的确认框与提示都是页面自己画的，不依赖浏览器原生弹窗——嵌在
> WebUI 的 iframe 里时，原生弹窗会被静默拦掉，表现就是「点了没反应、也没提示」。
>
> 顶部还多了一条 **外观** 栏：四套配色（深空 / 赛博 / 数据 / 素白）任选，
> 还能单独调主色。**配色与主色存在插件配置里**，刷新、换浏览器、重装都还在；
> 没手动选过配色时跟随 WebUI 的深浅色。
> 四套配色都过了 WCAG AA 对比度（正文最低 4.68:1），亮色主色会自动配深色文字。
>
> 面板的读法：**最上面一条是需要处理的事**（吸顶，没看过会标出来）；
> 再往下「当前可回收」是最大的一个数字；缓存层按 **要动手 / 正常 / 关着的** 分组，
> 要动手的按超得最多排最前，标题前带一颗呼吸的小点。关闭着的层折成一行、
> 危险操作平时是低调的（悬停才显形）、可调项默认折起来——
> 目的是打开面板第一眼就知道该管哪层，而不是在一堆同质卡片里逐行读。
>
> 打开面板时有一段开场：黑幕里浮着一圈小星点，标题「Orbit Cache」从一层
> 高斯模糊里显出来，副标题「娜莉灵」**只做渐变、位置完全不动**，
> 稳下来后标题进入缓慢呼吸，然后整块淡出。点一下或按任意键可立即跳过；
> 系统开了「减少动态效果」则完全不放。
>
> 三件事是按真机反馈改的：
>
> - **黑幕从第一帧就是不透明的**。之前是从透明淡入，那半秒里面板是亮的一闪而过，
>   看起来就是「先白闪一下才开始动画」，也容易被当成卡顿。
> - **不依赖脚本兜底**。万一 JS 整个没跑起来，纯 CSS 的计时会在 12 秒后
>   自己把黑幕撤掉，面板不会被永久挡住。
> - **退场会等数据，但最多等 2 秒**。数据慢的时候先显示「正在读取…」，
>   宁可让面板先出来给你看，也不要黑幕停在标题上像死机。
>
> 整条开场只动透明度与位移，模糊值从头到尾不重算（模糊由底层一层静态承担），
> 所以在平板上也是满帧。
>
> 首次使用会看到一张「首次设置」卡：告诉你**为什么现在连不上**、在哪加一段现成的
> NapCat HTTP 服务端配置（端口会避开你已占用的）、以及最后该填什么地址。
> 连上之后它自动消失。

> 也可以在 NapCat 的 `config/onebot11_<QQ号>.json` 里直接加：
> ```json
> { "network": { "httpServers": [
>   { "name": "Orbit Cache", "enable": true, "host": "0.0.0.0", "port": 3000, "token": "" }
> ] } }
> ```

**多个 Bot / 多个 NapCat？** 每个实例各加一个服务端（端口别撞号），
然后在本插件面板点「添加实例」，一行一个，各自独立的 Token 与清理间隔。

配多了容易有重复？面板上点 **「检测死实例」**。判据分两组：

- **磁盘证据（不依赖连接）**——同一个 NapCat 进程被配了两行时，地址可能写法不同
  （`http://1.1.1.1:3000` 与 `http://1.1.1.1:3000/`），但两份地址在
  `onebot11_<QQ>.json` 里指向的是同一个监听端点。这类**NapCat 挂掉时照样查得出**，
  因为它只读磁盘，一个网络请求都不发。
- **实测**——两个实例登录后是同一个 QQ 号，标为「可确认删除」。
- **连续 N 次探测连不上** → 只标为「仅提示」，**不提供删除**。
  「停用」和「此刻没启动」在这里分不清，误删一个在跑的 bot 比多一条提示糟得多。
  N 可以在面板上改（默认 3），探测最多每 15 分钟记一次。

上面两种可删的项，点一下只从配置里去掉那一行，**不会碰 NapCat 磁盘上的任何数据**，
删错了加回来就行。最后一个实例不允许删除——只想停用一个请把它的「启用」关掉。

面板首屏最上面还有一条 **「需要处理的事」**：实例连不上、发现重复、有层配置有误、
上次执行失败、定时体检没注册上……都汇在那里，按级别配色，点「知道了」后标为已读，
没看过的会标成「你上次关闭面板之后出现的」。

> 「实例连不上」会区分两种情况，因为要采取的动作完全不同：
> **磁盘上有对应的 `onebot11*.json`** → 地址没填错，多半是那个 NapCat 进程没起；
> **磁盘上找不到这个地址** → 地址填错了，或那个 NapCat 压根没开对外端口。
> 纯反向连接部署（NapCat 全都只配了 `websocketClients`）会单独说明
> 「协议缓存这层在你的部署上用不上」——那是环境说明，不是故障，不占红字。
>
> 面板读不出来（顶部那条「读取失败」）时，**每一张卡会同时变空**——
> 因为总览是一个请求，任何一处出错都会让整份数据发不出去。
> 所以：任何新增的体检项都必须单独兜住自己，坏了自己空着就行，
> 绝不能连累整个总览。空间地图/日志/垃圾那几项都是这么写的。
>
> 这条**只在面板里显示，不推送**。也就是说：不打开面板就不知道。
> 这是有意换来的取舍（不往聊天里发东西），所以它做得足够显眼、显眼到第一眼就能看见。
> 点「知道了」之后这一批会真的消失（安静 12 小时），不是点完还挂在首屏上；
> 12 小时后问题还在就重新提醒，并标明「又出现了」。

### 平台配置体检：找出重复的机器人配置

面板上点「查一下」。它读的是 **AstrBot 自己的 `platform` 列表**
（`data/cmd_config.json` 与 `data/config/abconf_*.json`），回答两件事：

- **重复配置**：同一个端口上有多条配置，而且**凭据也一样** —— 那就是同一条被改了名字
- **端口抢占**：同一个端口上有多条配置，但凭据不同 —— 两个都在抢，只有一个绑得上

为什么以前找不到：Orbit 只看自己连 NapCat 用的那几行
（`onebot_instances`），对 AstrBot 侧配了几条反向 WS 一无所知。
现在两边都看，所以「多出来的那个机器人配置」能被认出来。

**凭据只比指纹、不显示原文**——那串东西会直接进 web API，明文出去等于
把你的平台凭据发到浏览器。

这一块**只读，不改**。改平台配置要动 AstrBot 的核心配置，删错一条可能让某个
机器人直接掉线；这里只帮你把它准确地找出来，确认哪条多余之后回
AstrBot 的「机器人」页面自己删。

### 插件模块：状态未知 ≠ 已停用

停用插件时清内存靠的是「它确实停用了」这个判断。判不出来时（插件没在
`get_all_stars` 里、name 与 root_dir_name 都对不上），面板会标成 **「状态未知」**
并**跳过自动清理**——「不知道」不能当成「是」。把一个正在跑的插件从
`sys.modules` 里抽掉，它后续任何懒加载都会重新执行一遍模块代码。

### 日志到底在哪

「AstrBot 日志」这一层同时给两个数：**插件自己扫出来的**（`data/logs`、当前工作区的
`logs`、AstrBot 根目录、`ASTRBOT_LOG_DIR`，以及你在面板里填的「日志目录」），
和**上游报的那个**。两个都摆出来，因为它们不一致本身就是最有用的线索——
终端里明明满屏输出、面板上却报 0 B，几乎总是因为 AstrBot 写日志的地方和
`data/logs` 根本不是同一个。日志目录可配，填实际路径即可。

层里还会给出：多少个文件、最大的是哪个、几份是轮转、最旧的多旧、较上次多了多少。
**当前正在写的 `astrbot.log` 永远不删**——删掉被进程打开的文件不会马上释放空间，
之后的新日志会写进那个已删除的 inode，表现为「日志不见了」。

### 空间地图：先知道空间在哪

面板上点「统计一下」。它**一个字节都不删**，只是把几个地方按体积排个序。

你问过「NapCat 才占几 KB，那大头在哪」——答案就在这里：

- **NapCat 自己的 `temp` 本来就小**，那是中转管道，处理完就清空
- **图片视频在 QQ 客户端的 `nt_data/Pic`、`Video`、`File` 里**，插件平时看不见它们
- 统计结果里挑出大的那几个路径，填进下面的「自选媒体目录」，就纳入自动清理了

### 插件垃圾：只删不需要判断的

面板上点「扫一下」，会列出三类东西：

- `data/plugins/` 下**没有 `metadata.yaml`** 的目录 = 装到一半失败
- 压在插件目录里的 `*.zip` = 装完忘删的安装包
- `__pycache__` = 编译缓存，删了自动重建

点「一键清除」可以一次清掉全部，判据与逐项删除**完全相同**，只是少点几十次；
它仍然坚持先列清单、再确认，清完把**每一项的结果**列给你（删了哪些、哪些被年龄锁挡了）。
**最近 7 天内的目录与安装包一律不动**——「没有 metadata.yaml」也把**正在安装中的插件**
包含进去，没有这道年龄锁，清理会在它装完之前把目录连根删掉。
`__pycache__` 不受年龄锁：它每次导入 Python 都会刷新时间，拿年龄锁卡它等于永远卡住。
想让定时体检顺手清垃圾，在可调项里打开 `auto_clean_plugin_junk`（默认关着）。

**不判断「装了但没加载」**：停用、没加载、残留这三者在磁盘上长得一模一样，
猜错就是删掉一个正在跑的插件。删除前会校验路径仍在 `data/plugins` 内、
且确实满足该类条件，校验不过一律拒绝。

### 想清 QQ 收的图片视频？

面板可调项里的 **「自选媒体目录」**，每行一个绝对路径，填上就生效、留空就关着。

这一层**不自动搜索、不自动接管**任何目录（路径由你决定，比插件猜安全）。
填了之后只会删同时满足两个条件的文件：

1. 后缀在图片/视频/音频白名单里（`.jpg .png .gif .webp .mp4 .mov .mkv .webm .mp3 .silk` 等）
2. 修改时间超过「最小保留天数」（默认 30 天）

`.db`、`.json`、无扩展名、任何未知类型**一律不碰**，也不计入体积——
所以一个 10 GB 的 `nt_msg.db` 不会把这层逼到阈值之上。
家目录、当前工作区、AstrBot 数据目录会被直接拒绝。

## 二、它会自动做什么

| 层 | 触发时机 | 依赖 |
|---|---|---|
| 停用插件的内存模块 | 插件一被停用/卸载**当场**清理 | 不需要 NapCat |
| 插件目录垃圾 | 手动点「一键清除」，或开了 `auto_clean_plugin_junk` 后随体检 | 不需要 NapCat |
| AstrBot 临时文件 | 删超过 7 天的文件 | 不需要 NapCat |
| NapCat 协议缓存 | 每 12 小时一次，逐实例调用 `clean_cache` | 需要 NapCat 对外监听 |
| NapCat 文件缓存 | 目录总量 > 1 MiB 时，从最旧文件删到 85% | 只需要目录可见 |
| AstrBot 磁盘缓存 | 占用 > 16 MiB 时清理 | 不需要 NapCat |
| AstrBot 日志 | 占用 > 16 MiB 时清理 | 不需要 NapCat |
| 自选目录媒体文件 | 总量 > 512 MiB 时，只删超龄的媒体文件 | 需要你填目录 |

清理时对比清理**前后的磁盘剩余空间**并把差值报出来——“释放了多少字节”是插件自己算的，
磁盘不一定认（可能有进程还持着句柄）。两个数对不上时，你一眼就知道该怀疑什么。

清完之后面板会把**逐层结果**摊开：哪层动了、释放多少、哪层没动、为什么没动、哪层失败。
只弹一句「已清理 N 层」等于什么都没说——那正好是「按了强制全清但不知道有没有用」的由来。

每一层都会告诉你「**现在为什么没动手**」：是没超阈值、没配置、关着、还是上次失败了。
以前这句话藏在角落里，半天没动时根本分不清是哪一种。

### 容器里还有哪些地方会涨

「空间地图」现在按官方语义分层盘点，**只读，不删**：

- `data/plugin_data/<插件名>/` —— 每个插件一块，**哪个插件吃磁盘一目了然**
- 临时目录（下载的图片语音都在这，可清）
- 知识库（向量库，删了知识库就没了，所以只看不删）
- 数据库与它的 `-wal` / `-shm` —— 消息历史与附件只增不减，这是最容易膨胀的一块。
  WAL 长期不收缩说明上次没正常关闭

**插件数据残留**：`data/plugin_data/<名字>/` 还在，但那个插件已经不在了。

判据是**磁盘上的事实**：`data/plugins/` 下还装着（带 `metadata.yaml`）的目录，
逐个去 `plugin_data/` 里配对。这里踩过一个坑——早先拿 `plugin_data` 的目录名
和注册表里的名字**全等**比对，可前者是目录名（`root_dir_name`）、后者是
`metadata.name`（可以带 `astrbot_plugin_` 前缀，也可以不带），**结构上就可能
对不上**，于是正在用的插件被误报成残留。现在两边都归一化前缀再比，并且
**磁盘读不到时一个都不报**——读不到 ≠ 都没装。

也**不用注册表当主依据**：注册表会随启停变化，拿它判会把「已停用」误报成「已卸载」。

**只提示不删**：那些数据可能是你特意留的。

### 体检真的在跑吗

「上次体检」是过去时，「下次体检」是计划时。**计划时已经过去很久而体检没发生**，
说明任务压根没执行（handler 抛异常、进程重启后任务丢了）。这种情况以前在面板上
和「一切正常」长得一模一样，现在会进首屏的待办条。

另有两个**不自动运行**的板块，需要时手动点：

| 板块 | 做什么 | 风险 |
|---|---|---|
| **空间地图** | 纯只读统计：AstrBot 数据目录、QQ 客户端数据目录、你配过的目录，按体积排行 | 不删任何东西 |
| **插件垃圾** | 列出没装完的插件目录、遗留安装包、`__pycache__`，逐项确认后删 | 只删「不满足条件就是垃圾」的 |

### 缓存目录不用你填

`napcat_cache_dirs` 留空即可，插件会自己搜并接管，前提是同时满足：
1. 目录名像缓存（`temp` / `cache` / `cache_temp` / `temp_cache`）
   —— 这一条就自动排除了 NapCat 实例根目录（里面含 `config/` 与程序本体）
2. 里面没有关键配置文件（`onebot11*.json`、`napcat.json`、`webui.json`、
   `napcat.mjs`、`package.json` 等）

不满足的目录会出现在面板上但标为「不建议使用」，自动接管不会碰它们。
你手填 `napcat_cache_dirs` 时以手填为准。

**即使目录被手动填成实例根目录，清理时也不会删除关键文件名**——
这层保护独立于自动接管存在。

### Token 不用你填

每次连接前从 NapCat 的 `onebot11*.json`、AstrBot 自己的平台配置、环境变量里
收集候选，**逐个发真实请求验证**，留下第一个能通的。运行中收到 401/403 会
立刻重新解析并重试一次。所以 NapCat 重启换了 Token 也能自己跟上。

## 三、试运行：先看会不会删

面板顶部有 **「试运行（不删）」**。它会告诉你：

- 每个缓存目录当前多大、会不会超阈值
- 触发的话会删几个文件、共多少字节
- 前几个将被删除的文件路径
- 待清的插件模块数

**点它不会删除任何东西，也不改状态。** 确认无误后再点「立即体检」或等下一次自动体检。

| 指令 | 作用 |
|---|---|
| `/orbit` | 各清理层状态 + 调度速览 |
| `/orbit clean` | 立即无视阈值强制清理全部 |
| `/orbit on` / `/orbit off` | 开启 / 暂停自动清理 |
| `/orbit purge <插件ID>` | 立即清某个插件的内存模块 |

v1.x 的 `orbit_*` 旧指令仍可用，每次回复会附一行弃用提示。

## 五、配置项

面板上能改的都建议在面板改（保存即生效并重建定时任务）。
下面是配置页里值得知道的几项：

| 配置 | 默认 | 说明 |
|---|---:|---|
| `auto_enabled` | `true` | 总开关。关掉就不体检、也不清内存 |
| `sweep_cron` | `*/15 * * * *` | 体检频率。保存前会真正校验表达式（分段、范围、步长、区间方向），不合法则报错且**不写入** |
| `auto_clean_plugin_modules` | `true` | 建议别关。AstrBot 停用插件不清内存，靠它兜住泄漏 |
| `auto_adopt_cache_dirs` | `true` | 自动接管搜索到的安全目录（面板上可关） |
| `ui_theme` | 空 | 面板配色：`deep` / `cyber` / `matrix` / `light`，留空则跟随 WebUI 深浅色 |
| `ui_accent` | 空 | 面板主色，形如 `#38bdf8`。留空则用各套配色自带的主色 |
| `napcat_cache_threshold_mb` | `1` | 超过才清，删到 85% |
| `napcat_cache_min_age_minutes` | `10` | 正在用的临时文件不会被删，别调到 0 以下 |
| `astrbot_cache_threshold_mb` | `16` | 定得低是为了能真正触发；AstrBot 临时缓存删了会重新生成 |
| `astrbot_logs_threshold_mb` | `16` | AstrBot 自己的日志文件；正在写入的那个只清空内容不删文件 |
| `media_dirs` | `[]` | 自选媒体目录，**留空即关着**。只删图片/视频/音频后缀且超龄的文件 |
| `media_threshold_mb` | `512` | 自选目录里媒体文件合计超过才清，删到 85% |
| `media_min_age_days` | `30` | 比这个天数新的文件永远不删，**连「强制全清」也绕不过** |
| `log_retention_days` | `0` | 填 0 = 超阈值就清（旧行为）。填 7 = **只删超过 7 天的轮转日志**，当前正在写的 `astrbot.log` 永不删 |
| `unreachable_limit` | `3` | 连续这么多次体检连不上才标为「疑似失联」。调小会更早提醒，但一个只是暂时没启动的 bot 也可能被算进去 |
| `auto_clean_plugin_junk` | `false` | 让定时体检顺手清插件垃圾。**带 7 天年龄锁**，正在安装的插件不会被扫到 |
| `log_dirs` | `[]` | 日志目录。留空则依次找 `data/logs`、工作区的 `logs`、AstrBot 根目录与 `ASTRBOT_LOG_DIR` |
| `napcat_protocol_interval_hours` | `12` | 一天两次，对个人 Bot 够用 |
| `napcat_config_dirs` | `[]` | 额外搜索根，很少需要填 |
| `onebot_access_token` | 空 | 一般留空走自动解析 |

## 六、遇到问题看这里

| 面板显示 | 含义 | 该做什么 |
|---|---|---|
| `连接正常` | 通了 | 不用管 |
| `服务没启动` | 连接被拒（`ECONNREFUSED`） | NapCat 没在跑，或地址/端口填错 |
| `服务无响应` | 连上了但超时 | 防火墙拦截，或 NapCat 卡住 |
| `主机名解析失败` | DNS 解析不了 | 跨容器要写服务名且在同一网络 |
| `需要 Token` / `Token 无效` | 401/403，连接已建立 | 这时才轮到 Token |

**传输层出问题时，Token 输入框会被禁用**——改它不会有任何用。

> ⚠️ 看到「端口已被占用 / Address already in use」？**那不是插件发的**。
> 插件只做客户端，从不 bind 端口。那条消息来自尝试监听 3000 的进程
> （多半是你启动 NapCat HTTP 服务端的脚本），或者启动它时端口已被占用。

### 已知边界

- 读不到 NapCat 配置文件时，**没有任何程序能凭空知道它的 Token**，需手填。
  插件会如实报「需要 Token」，不会谎报成「无需凭据」。
- 四个 NapCat 适配器的 Token 各自独立。反向 WS 配的 token 不会自动适用于
  新加的 HTTP 服务端，要复用得在 HTTP 服务端上填相同值。
- 无论 NapCat 通不通，停用插件内存与 AstrBot 磁盘缓存这两层照常工作。

### 故障排查

| 现象 | 排查方向 |
|---|---|
| 面板显示「未注册」 | 检查 `sweep_cron` 是否合法，或 `auto_enabled` 是否已关 |
| 刚热重载过就显示「未注册」 | 本插件 `initialize()` 会自动重建任务；仍异常看日志 `Orbit Cache 注册定时任务失败` |
| NapCat 文件缓存层显示未启用 | 点「自动探测目录」看搜索结果；开着的自动接管会自动使用安全目录 |
| 停用插件模块数没归零 | 确认 `auto_clean_plugin_modules` 已开；重载后可用面板的「立即清理」 |
| 试运行说「不会删除」 | 当前占用确实没超阈值。点「强制全清」可以无视阈值立刻执行 |
